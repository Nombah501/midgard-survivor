# Persistent progression — Midgard Survivors 0.2.3

Static findings from the effective decompiled `analysis/src/` tree. References below are `file.gd:line` in that tree. “Call” means an in-process GDScript method, not an external API. `Save` is the profile autoload, `World` is `main.gd`, `Menus` is the active menu node. No live behavior was tested. Numeric projections and automation judgments are marked `[INFERENCE]`.

## 1. Save schema, lifecycle and offline boundary

- `Save.defaults()` has exactly: `version:1`, `zeny:0`, `upgrades:{}`, `cards:{}`, `card_slots:[]`, `stages:{}`, `rebirths:{}`, `looks:{}`, `unlocked:{}`, `classes:{}`, `pets:{}`, `pet:""`, `records:{}`, `stats:{runs:0,kills:0,mvp_kills:0,boss_kills:0,play_time:0.0,zeny_earned:0,cards_found:0}`, `achievements:{}`, `ach_claimed:{}`, `coins:0`, `seen:{}`, `settings:{music:0.8,sfx:0.8}`, `pacts:{}`. Lazy extensions include `classes[cid]={level,xp,stats[,rlv,rlv_called,looks_off]}`, `eternal:{id:count}`, `ymir`, `storage:[]`, `materials:{id:count}`, `loadouts:{cid:{slot:uid}}`, `tower:{builds,best,top,rewards[,wings,hel]}`, `quests`, `legacy_npcs`, `max_danger`, `danger_best`, `pet_skin`, `cook_level`, `dishes`, `cosmetics`, `sets`, `history`, `gacha_pity`, `wing_feathers_spent`, and discovered-counter/one-time migration fields (`save.gd:76–140,415–499,580–702,722–809,843–949,1054–1173,1178–1222,1385–1480,1665–1752,1795–1842,1937–2040,2137–2274`; `gacha_panel.gd:498–505`). This is not `Player.profile_of(cid)`: the latter snapshots effective meta mods, bank, copied compatible owned gear by UID, selected cards, pets, pacts, dishes and class fields at setup; changing Save mid-run does not itself reconstruct the current hero (`player.gd:521–538,640–674`).
- `settings` is persisted in the same file but distinct from earned assets; e.g. `upgrades_off`, `daily_run`, selected title, controls/options and cloud metadata live under it. Bought levels live under `upgrades`, and `GameData.meta_mods()` sums active levels, not raw levels. `reset_progress()` retains **all** settings but resets other root data; `reset_profile()` resets both and flushes (`save.gd:342–355,548–568,611–624,2277–2283`; `titles.gd:107–115`; `gifts.gd:49`; `game_data.gd:11315–11328`). `Engine/Object` metadata keys such as a hero's `tower_snap` are transient except when explicitly persisted (`menus.gd:13584–13607`). `RunSave` is a separate solo-run snapshot system, not the profile (`run_save.gd:74–112`; `main.gd:15676–15680`).
- `_name` starts `profile`: `user://<name>.json`, `.tmp`, `.bak.json`. Test flags select `profile_test` with fresh defaults/onboarded; coop preview selects `profile_coop`; editor selects `profile_dev`; latter two copy `profile.json` once if target absent. `_name != "profile"` blocks normal leaderboard submit, cloud eligibility and automatic gift polling; this is **not** a gameplay offline switch. Normal profile can be played locally while network features separately gate on their own state (`save.gd:20–59`; `leaderboard.gd:46–52,82–91`; `cloud_save.gd:75–79`; `gifts.gd:20–49`).
- `_read` checks `GDEC` magic and reads Godot encrypted-pass files or legacy plain UTF-8 JSON; returns only a dictionary. `load_profile()` tries backup only if primary exists but reads empty; uses defaults merged with loaded values (recurses only for existing nonempty default dictionaries such as `stats`/`settings`, preserves unknown keys; no general type validation), stamps version, then repairs. Legacy `records.json` only for empty normal-profile load. Web rescue writes the save bytes base64 to localStorage, reads back only a newer `settings.save_seq`, and web flush increments that sequence (`save.gd:117–140,184–243,269–275,288–301,309–339`).
- Repair order: strip removed `iceicle_card` dictionary keys/array entries recursively; infer legacy NPC access from stage clears, flag legacy completed achievements as claimed when claim map absent; refund removed `skill_slot` once (up to 25k z); remove `discipline` pact and reset its class stats; v2 reset → legacy stat halving/budget trim → v3 reset, each flag-guarded; restore missing recorded Sword Wings and owed Hel Requiems; create fixed Taekwon fists when applicable; grant one quest Eternal per completed card-reward quest (tracking `quest_eternals`); first load with `lock10_done` unset locks +10 storage gear. Recursive repair clamps refine above +10 (excludes `settings`) and flags `gear_edit` for overrefine/malformed potential; `Potential.edited` at that check only tests malformed/excess lines array or item tier above top, not total potential sanitization (`save.gd:117–173,209–232,248–266,500–506,1812–1949,2051–2057`; `potential.gd:33–58`).
- `mark_dirty` always emits `changed`, resets 2 s debounce; web timer 4× faster. `flush` no-ops unless dirty, clears dirty **before** I/O, writes encrypted JSON to tmp, backs up existing primary, then renames tmp; open/rename error logs, dirty isn't reinstated. Also flush on close/exit/pause/focus loss (`save.gd:62–73,277–301`). `Save.spend` decrements zeny and increments `stats.zeny_spent`, immediately flushes; `Save.pay` only decrements + marks dirty. They don't reject negative amounts; don't call them with negative. `use_material(id)` decrements one if available; `add_material(id,n)` can accept signed deltas; no protection from underflow in that latter setter (`save.gd:380–409,2241–2274`). Zeny from kills/pickup is persisted during play, unlike class XP (`main.gd:378–393,16009–16033`).

## 2. Class XP, stats and job paths

- Class level is **not** Base Lv. `class_progress(cid)` overlays stored fields on `{level:1,xp:0,stats:{}}`. `class_xp_need(cid,L)` is `roundi(int(600 × M × L^1.3) × R)`, where `M=3.0,R=1` at RLv 0 and `M=1.8,R=[1.5,1.75,2,2.25,2.5,2.75,3,3.5,4,4.5][RLv−1]` for 1–10. `class_climb_xp` sums from level 1 to cap−1. `add_class_xp` caps each RLv>0 award at `roundi(0.24 × class_climb_xp)`, subtracts requirements while levelling, discards surplus at cap, flushes and returns number of level-ups. Normal cap 30, reborn or `no_rebirth` cap 50. `[INFERENCE]` At least five max-size awards to complete an RLv climb. `_bank_run` guards double bank and awards `roundi(player.xp_gained × (1+0.08×(danger−1)) × (1.25 if featured else 1))` on either result; coop client uses host-reported XP/danger/featured. `Player.add_xp` includes `pace_xp × xp_mult` in `xp_gained`, so XP modifiers can feed this award. Result `class_xp` displays rounded pre-danger/featured `xp_gained`, not credited amount (`save.gd:722–809,1636–1637`; `game_data.gd:1008–1034,10021,10288–10289`; `player.gd:1559,4981–4989`; `main.gd:3012–3022,16009–16033`).
- `stat_points(cid)=floor((points_level−1)/2)+pact_value(cid,"points")`; `points_level` is current class level except RLv>0 uses at least its cap. `free_points=budget−sum(stored stats)`. UI only adds legal keys `str/agi/vit/int/dex/luk` with free points, each below `perm_stat_max(cid)=STAT_HARD_CAP=999`; UI merges pending allocations, not an arbitrary free respec. `set_class_stats` is an unchecked shallow copy and mark-dirty; `reset_class_stats` pays `400×points_level` and clears allocation. `rebirth_stats(cid)` adds +2 to each starting attribute for reborn or no-rebirth classes separately from point budget (`save.gd:758–785,1227–1286,1594–1595`; `ro_char_make.gd:438–460,571–581`; `game_data.gd:1008–1011,4689,4901`; `menus.gd:17566–17588`).
- `GameData.job_paths` yields `job2` then `job2_alt`. `Player.next_job(path=0)` clamps to an existing path, copies it, overlays `trans` only when reborn, removes `trans` and `skills_dance`, and handles female skills. `Player.can_job_change()` tests empty `job2`, class defines it, and Base Lv ≥20. `Player.job_change` itself only rejects already changed; selects path, updates performer/weapon/sprite/falcon, adds start skill and recomputes/full-heals. The world wrapper handles menu, FX and start-skill choices (`settings.job_skill_<job-id>`); normal game opens `show_job_change` when eligible/not busy/downed/loot-blocked. `auto_pick` invokes world wrapper directly (`--path` optional, otherwise random). No persistent class-path choice: run snapshot keeps job path, and run banking records discovery in `seen.jobs`. Job extra skill slot, trans extra +1 passive/+0 skill (`game_data.gd:4691–4709,8499–8506`; `player.gd:825–879`; `main.gd:4489–4504,14834–14873,16059–16064`; `menus.gd:7926–7975`; `run_save.gd:119–136`).

## 4. Equipment, refine, grading, storage and loadouts

**Roll/read.** `Equipment.make(id,n_slots)` initializes `{id,slots,refine:0,cards:[]}`; fixed override slot count and are `perm`. `roll_item(time,bonus)` first tries legend after 200 s unless guaranteed treasure. For `bonus>0` threshold `.0075 + legend_bonus + chest_legend + chest_extra`, for `bonus==0` `.0008+.2×legend_bonus`; none for negative. Excludes fixed/unique/face/duplicate run items and filters class/book/shield unless special chest; treasure also excludes owned storage IDs; weapon subgroup 30% if both choices present. Otherwise max rank `max(1,1+floor(time/180)+bonus)`, legal pool, own nonpurple weapon has 3 entries. Slot weights `[54,27,13,6][i]×1.6^((time/160+bonus)×(i−1)/2)`, mobs with negative bonus cap at 1 slot, positive chest minimum 3, definitions with `purple` force 3. Rolled nonfixed slot≥1 gear gets random trait. Slots 0/1/2/3 are grey/green/blue/purple with base stat multipliers ×1/1.3/1.6/2; `rank`, `legendary`,`unique`,`grade` are separate. `score=50 if legendary +8×rank+10×base slots+3×refine+6×card count` (does not value actual modifiers/extra socket/trait/grade/potential). Refine scales positive base mods by `1+.15×r` for refinable pieces (`crit_dmg` at one third growth), adds definition's per-refine mods, and weapons gain +5% damage per level above safe. Potential mods add, positive two-hand mods scale, then grades/cards add (`equipment.gd:186–204,269–272,290–304,414–503,541–611,862–865`; `game_data.gd:7375–7400,7471–7473,7588–7596,7682–7687,8923`).

**Refine.** `Equipment.refinable(it)`, `ore_for(it)` (weapon Oridecon, otherwise Elunium), `weapon_level(it)` (explicit `wlv`, legendary 4, rank-1 first class weapon 1 / other 2, otherwise `min(4,rank+1)`), `refine_chance(it)`, `refine_safe(it)`. Base chance by **current** +0…+9:

| Rate key | Chance percentages | Guaranteed through |
|---|---|---:|
| `w1` | 100 100 100 100 100 100 100 60 40 19 | +7 |
| `w2` | 100 100 100 100 100 100 60 40 20 19 | +6 |
| `w3` | 100 100 100 100 100 60 50 20 20 19 | +5 |

## Automation boundary: direct transactions versus world/UI

**Can automate directly after checking normal preconditions** `[INFERENCE]`: query loaded profile and derived budgets; set legitimate settings, stage danger/oath preferences, validated stats/appearance, reset stats with billed API; unlock class; select owned starting loadouts (guarded Menu method or equivalent checks), presets, Super Novice choices, known dishes, pacts, active pet/skin and owned cosmetic/title; use Kafra/Sage purchases via callbacks, cook upgrade, trait reroll, Eternal fuse/set/unset, achievement check/claim, wings refine/awaken, favorite/lock storage, rename/delete/lock real tower snapshots; first-trans and RLv mutators after normal eligibility and explicit reset decision. Persist via existing mutators/flush; replay of paid operations is not idempotent, and reading a live dictionary does not grant license to mutate it. See §1–§12 for exact guards.

**Drive normal world/menu sequencing** `[INFERENCE]`:

- Run start/end, class/job draft (use `World.do_job_change`, not only `Player.job_change`), item/card/egg pickup, boss kills/Ymir, karma choices/route, quest rewards, end keep (including swap/return/leave, snapshot links and leftover cash-ins); bank/award methods are callbacks, not freestanding economy actions.
- Refine/grade/socket selection and confirmation (real selected UID/ore), storage sale/valuable confirmation, Star Smith lock/risk/tear confirmation, Gacha and fusion if using normal menus. Grade/socket/Star Smith/Gacha/fusion commit on action **before** animation; don't repeat a press when just waiting for busy/animation state. First rebirth's Valhalla route and RLv double-confirm if using UI; presentation/no-op bypass entry points are not reward sources.
- Normal gift service polling/notification; don't synthesize requests or awards. Tower entry consumes a real build; navigate camps, stairs, blessing and wheel prompts, raids, Hel hazards and end UI as needed. Training is a tool/benchmark surface, not an acquisition path.

**Do not call as free grants or automate destructive resets** `[INFERENCE]`: raw award setters (`add_zeny/add_coins/add_material/add_card/add_pet/add_ymir_fragment`, `add_to_storage`, `_found_unique`, `tower_cleared/hel_cleared/give_hel_rose`), internal/debug unlock flags, direct `Save.data` rewrites and `reset_profile/reset_progress` outside explicit user intent. These functions assume upstream game events or UI safeguards; bypassing them is not equivalent to farming.
