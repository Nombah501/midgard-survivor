# Use a signed, anonymous App update channel

Status: accepted (Operator, 2026-11-22). Supersedes the release source and credential in [ADR 0007](0007-app-self-updates-versioned-user-dir.md), not its installation, handoff or rollback.

The source repository and GitHub Releases stay public. An Operator-owned Cloudflare R2 bucket serves stable App updates anonymously over a custom HTTPS domain. The App pins a minisign Ed25519 public key rather than trusting the host or a GitHub PAT to authorize executable code. PyNaCl uses the small packaged libsodium binding on Linux and Windows; it avoids implementing Ed25519 ourselves or requiring the Operator to install a verifier executable.

## Format and publication

- `stable/manifest.json` is UTF-8 JSON with `schema: 1`, `channel: "stable"`, `version`, positive integer `sequence`, `expires_at` (Unix seconds), `changelog` (Markdown text from the matching `## [version]` section of `CHANGELOG.md`), and both `archives.linux` and `archives.windows` (`name`, `size` in bytes, lowercase `sha256`). Each archive is stored at `archives/<sha256>/<name>`.
- `signatures/<SHA-256 of the exact manifest bytes>.minisig` is the detached minisign signature (prehashed `ED`, Ed25519 over BLAKE2b-512). The digest path pairs the correct signature with the manifest even across a publication or a CDN cache. No manifest metadata is trusted until the signature verifies.
- GitHub Actions verifies the OS build checksums, publishes the public GitHub Release, and for stable tags runs `packaging/publish_update.py`. It conditionally creates immutable archives and signature before writing `stable/manifest.json` with an R2 ETag precondition and `Cache-Control: no-store, no-transform`. The publisher rejects an older version or sequence; a successful run can be retried idempotently. GitHub's CI run number is the sequence; do not reset the numbering or replace the active bucket without preserving the published manifest, signature and archive objects. Publish a new stable version within the 180-day expiry window. Publish a fix under a **new version**, never overwrite an R2 archive.
- The service stores the highest authenticated, unexpired sequence and its manifest digest in `app-update-sequence.json` before attempting archive download. It accepts equal sequence only for exact same manifest bytes. Local install/rollback doesn't reset this file. Leave it intact during recovery. A staged release can only be queued while the authorizing manifest is unexpired and matches the floor; after handoff is queued the independent watchdog follows ADR 0007. The wall clock needs to be correct.

## Window model API

- `app_update.request_update_check(platform)` only atomically queues an App check. It can raise `OSError` if app data is unavailable. The installed service consumes the request asynchronously (including during an AFK session); startup and 24-hour checks continue. This is separate from the Game update command.
- `app_update.read_update_status(platform)` exposes `version` (selected installed release), `latest_version` and `changelog` (last accepted manifest, which may describe the selected release or a version excluded after rollback). The changelog is plain text from Markdown; don't render it as HTML. Before any accepted manifest, latest version is `None` and changelog is empty.
- `last_checked` is Unix seconds for the last completed attempt (including failures), or `None`; `last_result` is `up_to_date`, `staged`, `excluded`, `error`, or `None` before a signed-channel check. `reason` explains an error. A failed check can retain the last authenticated version and notes while clearing `staged`. Existing previous, staged and switch fields still describe the local handoff.

## Operator: one-time setup before the first stable tag

1. Sign into the [Cloudflare dashboard](https://dash.cloudflare.com/), enable R2 Object Storage, and add the Operator's domain as a DNS zone in the **same account**.
2. Under **R2 Object Storage → Overview → Create bucket**, create a dedicated bucket (e.g. `midgard-farm-updates`, Standard storage); note its name and the exact S3 API endpoint shown for that bucket (`https://<ACCOUNT_ID>.r2.cloudflarestorage.com` for the default jurisdiction). Keep this bucket for public release objects only.
3. Under the bucket's **Settings → Custom Domains → Add**, connect a dedicated host such as `updates.your-domain.example` and wait until it is **Active**. Leave Public Development URL (`r2.dev`) disabled. Bypass cache for `/stable/manifest.json` and do not put login or browser challenges in front of the download host. In `src/midgard_farm/core/_app_releases.py`, replace `UPDATE_BASE_URL = "https://replace-with-operator-updates-domain.invalid"` with that HTTPS origin before building.
4. Under **R2 Object Storage → Account Details → API Tokens → Manage**, create an **Account API token** with **Object Read & Write** scoped only to the release bucket. Copy the generated **Access Key ID** and **Secret Access Key** (shown once). No R2 or GitHub credential is entered on either farm machine.
5. On a trusted provisioning machine, install minisign and run `(umask 077; minisign -G -W -p midgard-update.pub -s midgard-update.key)` outside the checkout. Set `MINISIGN_PUBLIC_KEY` in `src/midgard_farm/core/_app_releases.py` to the second line of `midgard-update.pub` (the Base64 key, not the comment). Keep an encrypted offline backup of the unencrypted CI signing key; never commit the `.key` file.
6. In the GitHub repository's **Settings → Secrets and variables → Actions → New repository secret**, set `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ENDPOINT` (full S3 API URL), `R2_BUCKET` (bucket name), and `MINISIGN_SECRET_KEY` (the **entire** contents of `midgard-update.key`). Restrict who can push release tags or modify CI. Only the stable release step receives these secrets; GitHub auth for the public Release is the workflow's built-in token.
7. Revoke the old PAT in GitHub settings, if one was created. Review the public key fingerprint and the domain in the source, finalize the release notes, and tag the matching App version only after provisioning. Verify the published manifest and its detached signature from the public HTTPS host without credentials. Install the first signed-channel archive from the trusted GitHub Release using setup; revoking the PAT is what disables old clients' remote updates. Setup and the new service remove the obsolete local credential without lowering the floor.

If the signing key is lost or compromised, stop publishing with it and prepare a trusted manual installer with a new pin. The publisher with the new pin cannot verify the old manifest: record the last trusted sequence, archive the old channel head offline, then remove only `stable/manifest.json` from R2. Keep the immutable archives and signatures. Rotate the CI signing secret, publish the replacement with a higher sequence, and install it manually because the old client cannot authenticate the new pin. Preserve the saved client floor. Never upload private keys to R2.
