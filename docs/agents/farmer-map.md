# Farmer code map

Where the AFK farmer's behaviour lives. Function names, not line numbers: `grep -n '^func <name>' farmer/src/farmer.gd`.

## Run lifecycle (`farmer/src/farmer.gd`)

`_process` drives one phase per frame:

1. `idle` → `_prepare_run`: choose target, snapshot pre-run state, `world.start_run`, checkpoint `run`.
2. `run` → `_tick_run`; the run ends via the game or `_end_run_safe`.
3. `settle` → `_begin_settle` / `_check_settle` until the end screen.
4. `keep` → `_do_keep`: keep, sell the rest, verify the profile save, checkpoint `settled`.
5. `maint` → `_do_maintenance`, then `_complete_run`: verify the profile save, checkpoint `settled` again, `_account_run` (totals, journal `_append_run_log`, `_update_arm`), checkpoint `idle`.
6. Terminal: `_finish(reason)` (verified save, `phase=done`) or `_fail_session(reason)` (`phase=failed`). An unverified save preserves the previous checkpoint and is not retried by the app supervisor.

Cross-cutting:

- Status (supervisor contract): `_write_status`, `_totals`.
- Checkpoint and crash recovery: `_write_checkpoint`, `_restore_checkpoint`, `_journal_has`; session identity from `FARMER_SESSION_ID`.
- Tower (`_validate_tower_choice`, `_pick_tower_snapshot`, `_launch_tower`): catalog checkpoints and Hel lock state come from `Save`; Start ranks all eligible unlocked snapshots by level, XP fraction and recency. The checkpoint binds a stable snapshot ID to the run ID before native `start_tower` consumes it. On restart, recover a provable settled result; 0.2.7 does not save an active Tower run for resumption, so an unresolved intent refuses with `tower_intent_unresolved` without another spend.
- Tower gameplay (`_tick_tower`, `_steer_tower`): use native autopilot, speed gates, camp/stairs/blessings/wheel and combat, with farmer telegraph avoidance for field/raid attacks and Hel fog/Judgement. Close reachable Niflheim portals, intercept Hel Naght souls when no higher-priority raid objective is active, and collect prizes before taking the native return portal. Death or Finish settles one run per Start (`tower_finished`); floor 100 is not a win. The journal keeps the start floor, highest cleared floor, end cause and spent snapshot. Autopilot stays on through settlement and the Loadout loader is never used.
- Ordinary settlement (`_save_tower_snapshot`) mirrors the native end-screen eligibility gate locally. The catalog marks farmer snapshots; a stronger one may replace the previous unlocked farmer snapshot, never a manual or protected entry. A full unlocked list is left unchanged and logs `TOWER_SNAPSHOT_SKIPPED full`.
- Save verification: `_flush_profile_verified` reads this boundary's unique marker back from the game's final profile before the farmer publishes a result.
- Lethal hits: `tools/patch_player.py` emits `Player.farmer_fell` after a native revive or before terminal death. `_on_player_fell` logs the cause and remaining leaves immediately; the result journals `falls_by_mechanic` (including the final fall), which the app retains per run in session history. Old journals without this field have unknown fall counts, not zero.
- Operator commands and limits: `_check_command` (claims `user://farmer_command`; legacy `farmer_stop` = finish), `_check_limits` (`max_minutes`, `max_runs`, `stop_after_wins`), both ending in `_request_finish`.
- Movement: `_steer_goal` selects the target. Raid/Morroc mechanics keep precise `_steer_direct` steering, including the blocked-portal detour. Field goals use `_steer_field`: a clear segment or a cached route over the same `RoMap.cell_walkable` tiles as the player. A blocked or stalled segment triggers a re-plan; goals that still fail cool down briefly. With no goal, `_steer_open_ground` uses per-map clearance and escape directions to leave narrow pockets while preferring the native combat direction on open ground.
- Hazards: `_avoid_field_hazards` and `_avoid_raid_hazards` read native cast and wave state. `_avoid_hazards` checks discs, strips and dash corridors against walkable movement, the arena rim and pillars, keeping the normal goal when its path is safe. A `starfall` wave supplies continuous orbiting as the preferred move; native raid movement still handles objective mechanics.
- Level-ups: `_draft_player` calls the game's manual-play auto-picker using the saved per-class priorities, caps, fill and ban choices. The farmer keeps the game’s menu automation for other dialogs and preserves the saved manual-play toggle across `start_run`.
- Goal order (`_steer_goal`): held altar channel, Morroc mechanics, then the best altar (`_map_altar_goal` for map-wide, `_best_altar` for cautious), then the golden runner, then pickups. `_best_pickup` only chases pet eggs (`tame`), plus chests when no pet fetches them: the magnet pulls gems, zeny and ores, the pet fetches chests, and an MVP victory pulls cards. Below hero level `EARLY_LEVEL` (20) map-wide altars count only within `EARLY_ALTAR_RANGE` and with at most `EARLY_ALTAR_CROWD` enemies around them (`ALTAR_SKIP reason=too_early`, re-evaluated), and the runner is ignored.
- Combat steering: with no goal the hero moves by `_combat_steer`, a port of the game's `Bot.steer` scoring. The native version treats any class with a `cast` pose (the whole Acolyte line) as ranged and holds 4–7 units off, so a melee basic attack never lands; the port takes the stance from `def.basic.ranged`, prefers lone targets and drops the loot pull.
- Endless strategy (`farmer/modes/endless.json`): `altar_policy: "map-wide"` searches all of `Altars.waiting`. It keeps altar priority order, comparing route distance within each priority and skipping candidates that cannot be reached and channelled within their remaining life (`ALTAR_SKIP reason=expires_first`). Baldur is taken as soon as possible like any altar; if its four-second calm channel is interrupted, it gets one retry in the MVP portal window, where the game freezes altar lifetimes and the route avoids the portal trigger. A channel gets five game seconds without progress before abandonment. `ALTAR_TAKE` and `ALTAR_SKIP` include the raid state and altar instance. Hel altars are taken only on a forced dark side.
- Karma route (`karma_route` from the window's Route; ADR 0011): `valhalla` forces `path = "light"`, `hel` forces `"dark"`, `rotate` rolls a side once per run (`KARMA_SIDE side=… route=rotate run=…`, checkpointed in `pre_run`); `natural` (test scenarios only) leaves the game's karma alone. After each regular MVP the farmer takes the native karma portal and waits for `VALKYRIE_KILLED` (light) or `RANDGRIS_KILLED` (dark) before continuing. During Reginleif's Caída wave, `_kite_starfall` runs a continuous arc inside the rim and outside the crystals. Routes log remaining revives and cumulative leaves spent; a refused route logs `KARMA_ROUTE_SKIP`. `--scenario hel-route-drill` checks the dark route end to end.

## Around the game

- `farmer/tools/supervisor.py`: restart, backoff, quarantine (with run.sh's preflight `detail`), notifications, the single-supervisor lock, the systemd unit (`--print-unit`). Its tests are in `farmer/tests/test_supervisor.py`.
- The app supervisor (`src/midgard_farm/core/supervisor.py`) commits Pause/Resume to `session.json` before acknowledging the command or delivering it to the game. A replacement child uses that intent at boot. `outcome.json` commits a terminal outcome together with its quarantine evidence; the per-session `quarantine.json` is a diagnostic copy.
- The app supervisor's run-clock watchdog is independent of `_check_watchdog` in the game. A portal approach is outside the arena and still has the 180-second run-clock deadline even with fresh heartbeats. Inside the arena the deadline is 1200 seconds; Morroc's local run-clock exemption does not reset either supervisor deadline.
- `farmer/run.sh`: preflight (exit 78 = unfixable: game/patch/build, cfg not a JSON object or using keys from `farmer/obsolete_config_keys.json`, profile dir not writable or below `FARMER_MIN_FREE_MB`), the launcher `flock` (the only single-instance guard), network isolation for supervised sessions, backups and known-good. Its tests are in `farmer/tests/test_run_sh.py`.
- Contracts and operator docs: `farmer/README.md` (AFK session, commands, isolation/backup, status). Decisions: `docs/adr/`.

## Verification

- `farmer/tools/check.sh`: static checks plus pytest when tools, tests or scripts are staged. Needs no game.
- `farmer/tools/verify.sh [--scenario…]`: real-game scenarios on a sandbox copy of the profile. Run `./build.sh` first after any `farmer.gd` change. One game per machine: runs queue on `.sandbox/verify.lock`. `--supervised-*` and `--soak=HOURS` run the real supervisor through `tools/drive_supervisor.py`; `tools/soak_check.py` judges a soak (tests: `farmer/tests/test_soak_check.py`).
- `.venv/bin/python -m midgard_farm.verify --scenario one-run` (repeat `--scenario` to select more), `--all` for all supported headless bounded scenarios, or `--soak=HOURS` for the Linux-only soak. Run from the checkout root with the game closed and an app-built farmer patch. If the legacy patch is still mounted, restore the official patch before using the Python verifier. The CLI copies the profile, queues on `.sandbox/verify.lock`, and saves logs and `summary.json` under `.sandbox/verify-*`; `--keep` also retains successful sandbox profiles. The external-kill scenario is Linux-only and reported as skipped by `--all` on Windows. CI uses only fake games.
- `--scenario watch-mode` runs one supervised windowed run using the same Start setting as the AFK switch. Start it from a graphical desktop and observe the game window; the verifier checks that the supervisor finishes without restarting and retains the raw game exit in its `outcome.json`. `--all` stays headless.
- `--scenario blocked-portal` puts the hero and an open MVP portal on opposite sides of an obstruction in Prontera Field. It passes only if the hero enters the native arena; it does not require a boss kill.
- `--scenario field-navigation` uses native walkability, altar channelling and pickup collection on a deterministic sandbox maze. It requires the hero to reject an altar that would expire en route, take a farther reachable altar, pick up a pet egg behind the wall without stalling, and escape the cul-de-sac without a goal.
- `--scenario field-charge-drill` forces four native Baphomet charges from different directions at D30/37 oaths, with no leaves. It requires zero dash contacts, falls, or deaths.
- `--scenario valkyrie-drill` forces early sandbox Valhalla fights at D30/37 oaths. It isolates one native ability per encounter and requires ten complete six-mark Caída waves with Doom active, no leaves, and zero contacts, piercing hits or deaths.
- `--scenario mvp-mechanics-drill` tests five native trials each of Reginleif's Lanzas de Valhalla, Orc Lord's arena Terremoto, and the field Hibram's Golpe aplastante. It requires all strikes to resolve with zero contacts, hits, deaths or fall counts.
- `--scenario hell-rotation-payon`, `hell-rotation-orc_dun`, `hell-rotation-nameless` and `hell-rotation-turtle` run the full Hell strategy at D30/37 in those locations, with the original `hell-rotation` finale and route checks.
- `--scenario flush-fail` blocks the native profile write at keep and requires a failed exit, the original run checkpoint, and no journaled or credited rewards.
- `--scenario tower-snapshot-parity` runs two ordinary D30 runs to progressively higher levels in the profile copy. It checks that the farmer's single saved snapshot is replaced and that all nine unlocked and one locked manual fixtures retain identical saved content at both settlement boundaries.
- `--scenario tower-one-run` starts a normal Tower at the configured native checkpoint and publishes Finish after two floors if still alive. It requires an open Tower and an eligible snapshot in the profile copy; the verdict checks exactly one spend, saved character preparation, native settlement without online submission, checkpoint intent, and journaled floors/end cause.
- `--scenario tower-crash-recovery` crashes at the Tower intent and after `start_tower`, relaunches with the same session, and requires `tower_intent_unresolved`, at most one spend, an unchanged profile and no journaled run.
- Duration: bounded scenarios take minutes (`location-rotation`, `native-progress-parity` and `keep-unowned-legendaries` together: 583 s wall). `hell-rotation-*` and other full Endless runs at D30 take 15–40 min wall and can outlast a 30-minute subagent (a Payon run passed 35 game minutes at the limit). Start long scenarios as a background job from the main session; give subagents the evidence directory to analyse.
- The real profile and the real install (`./install.sh`) are the operator's. Leave them to the operator.
